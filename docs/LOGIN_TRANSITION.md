# Neo greeter 登录过渡

认证成功后，daemon 暂缓回复认证 helper，先让 neo greeter 做 150 ms
过渡。此时用户会话尚未进入 PAM openSession，避免先切 VT 再播放动画。
动画结束后等待各个已显示窗口完成两次帧提交（排除动画结束时已在渲染中的旧帧），再确认可以继续启动。
正常流程没有额外的黑屏停留，也不等待桌面就绪通知。

| 登录路径 | 当前策略 |
| --- | --- |
| 共用同一个 X server 的 X11 → X11 | 控件淡出，保留壁纸，退出前将壁纸画面设为 X 根窗口背景 |
| 独立 X server 的 X11 → X11 | 所有屏幕整体渐黑 |
| X11 → Wayland | 所有屏幕整体渐黑 |
| Wayland A → Wayland A | 所有屏幕整体渐黑；目前没有跨实例画面交接接口 |
| Wayland A → Wayland B | 所有屏幕整体渐黑 |
| Wayland → X11 | 所有屏幕整体渐黑 |
| 恢复已有用户会话 | 渐黑完成后再激活已有会话 |

相同合成器 ELF 不等于共用显示实例。当前不通过 ELF 名称匹配假定支持
无黑屏交接。后续若接入具体合成器的交接接口，应在确认交接能力后选择
保留画面的路径，其他情况继续使用渐黑。

前端等待末帧的上限是 300 ms，daemon 等待整个过渡的上限是 800 ms。
超时会继续登录，不让渲染卡顿阻塞认证 helper。会话启动失败会取消过渡，
恢复登录界面；自动登录和未声明支持过渡的旧 greeter 保持原有流程。
X11 的根窗口背景只承接桌面绘制之前的空档；目标桌面仍可自行重置背景。

验证包括认证 helper 协议的延后/恢复/取消、前端协议拆包与重复确认、
双窗口渐黑和失败恢复。真实 VT 切换及各桌面启动表现仍需在虚拟机或
专用测试机器验证，不应在日常桌面上重启显示管理器做自动化测试。

## 维护入口

- `Display::beginTransition()` 决定过渡方式并暂停 helper；
  `completeTransition()` 负责恢复会话启动。
- `MainWindow.qml` 的 `handlePrepareTransition()` 和 `handleLoginFailed()`
  分别处理动画启动和失败恢复。
- `LoginTransition` 单独管理末帧等待。`Start()` 为本次过渡建立窗口连接，
  `FrameSwapped()` 统计提交次数，`Complete()` 确认放行；`Cancel()` 统一停止
  定时器并销毁连接上下文，避免旧回调影响下一次过渡。
